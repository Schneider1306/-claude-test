# Экономика юридической практики — инструкция для Ильи

Это персональное приложение для учёта дел, оплат, времени и экономики вашей
юридической практики. По умолчанию оно работает **только на вашем
компьютере**, не отправляет никакие данные в интернет и не требует
подключения к сети для повседневной работы.

Все данные хранятся в одном файле: `data/legal-practice.db`.

Если нужен доступ с телефона (например, с iPhone) из любой точки — это
отдельный, необязательный режим с размещением в интернете и паролем на
вход. Инструкция: **[DEPLOY.md](./DEPLOY.md)**.

---

## 1. Что нужно установить один раз

1. Скачайте и установите **Node.js** (версия 20 или новее):
   https://nodejs.org — выберите версию "LTS" и установите с настройками по
   умолчанию.
2. Скопируйте папку с приложением на свой компьютер (например, на Рабочий
   стол или в "Документы").

Больше ничего устанавливать не нужно — все остальные компоненты (база
данных, библиотеки) приложение подтянет само.

---

## 2. Как запустить (Windows)

Дважды щёлкните по файлу **`start-windows.bat`** в папке приложения.

Откроется чёрное окно с текстом — не закрывайте его, пока пользуетесь
приложением. При первом запуске оно:

1. установит необходимые компоненты (1–3 минуты, только один раз);
2. создаст базу данных и заполнит её стартовыми настройками и справочником
   услуг;
3. соберёт и запустит приложение.

Когда в окне появится строка `Ready` — откройте браузер (Chrome, Edge,
Яндекс.Браузер — любой) и перейдите по адресу:

```
http://localhost:3000
```

Чтобы **остановить** приложение — закройте чёрное окно или нажмите в нём
`Ctrl+C`.

Чтобы **запустить снова** — просто ещё раз дважды щёлкните
`start-windows.bat`. Все ваши дела, платежи и время никуда не денутся: они
хранятся в файле `data/legal-practice.db`, а не в браузере.

### Как запустить на macOS / Linux

Откройте терминал в папке проекта и выполните:

```bash
npm install
npm run db:setup
npm run build
npm start
```

Дальше — так же, откройте `http://localhost:3000` в браузере.

Для ежедневной разработки (с автообновлением при правках кода) используйте
`npm run dev` вместо `npm run build` + `npm start`.

---

## 3. Как обновить данные (например, каталог услуг или настройки)

Все настройки редактируются прямо в приложении, в разделе **«Настройки»**:

- «Цели и расходы» — желаемый личный доход, аренда, интернет, резерв и т.д.;
- «Налоги» — режим (НПД / УСН / свой), ставки, лимит НПД;
- «Справочник услуг» — можно менять цены, время, описание, добавлять новые
  позиции, деактивировать старые (старые дела при этом не меняются — цены
  в них "заморожены" на момент создания);
- «Данные и резервные копии» — резервные копии, экспорт, восстановление.

Никакие файлы вручную редактировать не нужно.

---

## 4. Резервные копии и восстановление

- При каждом запуске приложение **автоматически** создаёт резервную копию
  базы данных в папке `data/backups/`.
- Хранятся последние **10** копий, более старые удаляются автоматически.
- В разделе «Настройки → Данные и резервные копии» можно:
  - скачать свежую резервную копию себе на диск (например, в облако или на
    флешку — это ваша "страховка" на случай поломки компьютера);
  - экспортировать все данные в JSON (для архива или переноса);
  - экспортировать список дел в CSV (открывается в Excel);
  - **восстановить** базу данных из ранее скачанного файла резервной копии.

При восстановлении:
1. Приложение проверяет файл (это действительно корректная база данных
   SQLite с нужными таблицами) — испорченный или случайный файл будет
   отклонён.
2. Текущая база данных автоматически сохраняется как "аварийная копия"
   перед заменой — вы ничего не потеряете, даже если восстановите не тот
   файл.
3. После восстановления нужно **перезапустить** приложение (закрыть чёрное
   окно и снова запустить `start-windows.bat`), чтобы изменения вступили в
   силу.

---

## 5. Важно про конфиденциальность

- Приложение не отправляет данные в интернет и не содержит слежения
  (телеметрии).
- Файл базы данных на диске **не зашифрован**. Если на компьютере
  установлен пароль пользователя Windows — это защищает от посторонних,
  но не заменяет шифрование диска. Не храните в системе больше медицинских
  и личных данных, чем необходимо для работы.
- По умолчанию карточка дела использует **обезличенный код клиента**
  (например, «КЛ-014»), а не ФИО — старайтесь придерживаться этого
  подхода.
- Удаление дела — «мягкое»: дело помечается удалённым, но не стирается
  физически, и его можно восстановить прямо из карточки дела.

## 6. Краткая карта разделов

| Раздел | Что там |
|---|---|
| Главная | Сводка за месяц: доходы, задолженность, налоговый резерв, прогноз личного дохода, лимит НПД, просрочки |
| Дела | Список всех дел с поиском, фильтрами и экспортом в CSV |
| Новое дело | Пошаговый мастер создания дела (10 шагов) |
| Карточка дела | Вкладки: обзор, этапы, заседания, время, оплаты, расходы, экономика, документы, история |
| Платежи | Все платежи по всем делам: плановые, фактические, возвраты, возмещения |
| Учёт времени | Все записи времени по всем делам, с таймером на карточке дела |
| Календарь | Заседания, сроки этапов, плановые оплаты, просрочки — единой лентой по датам |
| Сценарии | Конструктор месяца: смоделируйте ожидаемые дела и посмотрите прогноз дохода |
| Аналитика | Графики и таблицы: доход по месяцам, прибыльность по типам дел, использование времени |
| Настройки | Цели, расходы, налоги, каталог услуг, резервные копии |

## 7. Решения, принятые самостоятельно при разработке

Часть мелких вопросов в задании не имела единственно верного ответа. Ниже
— какие решения были приняты и почему, чтобы вы могли их скорректировать,
если что-то не подходит.

1. **Формат внутреннего номера дела** — `ГОД-###` (например, `2026-001`),
   сквозная нумерация по годам.
2. **Срочная надбавка в мастере создания дела** применяется только к
   начальному этапу (как явно указано в ТЗ — "надбавка... не ко всему
   делу"). Если срочным должен стать другой (позже добавленный) этап —
   это можно включить вручную в карточке дела, на вкладке «Этапы», у
   любого этапа отдельно.
3. **Скидка в мастере** применяется одинаковым процентом ко всем строкам,
   которые вы добавляете в рамках одного мастера (начальный этап,
   заседания, экспертиза, доп. этапы). После сохранения дела скидку можно
   менять по каждому этапу отдельно на вкладке «Этапы».
4. **Контрольная (внутренняя) ставка** — единая для всей практики величина
   (не зависит от типа клиента конкретного дела). Так как режим НПД имеет
   две ставки (4% с физлица, 6% с организации/ИП), для расчёта контрольной
   ставки используется ставка "от организации/ИП" (6%) как более
   консервативный ориентир — это в точности соответствует контрольному
   примеру из задания (582 613 ₽ / 8 200 ₽ в час). Ставка налога **по
   конкретному платежу** при этом всегда считается правильно — по
   фактическому типу плательщика.
5. **Налог по платежам** считается и сохраняется только для платежей типа
   «фактически получен». У плановых платежей, возвратов и возмещений
   расходов налог не рассчитывается (эти суммы не являются полученным
   доходом на момент фиксации).
6. **Вкладка «Документы»** в карточке дела содержит ссылку на печатную
   версию коммерческого предложения. Хранение файлов дела (сканы,
   договоры) на диске в этой версии не реализовано, чтобы не создавать
   лишнее место для хранения персональных и медицинских данных сверх
   необходимого. Такие файлы рекомендуется хранить в отдельном защищённом
   хранилище со ссылкой на обезличенный код клиента.
7. **Календарь** сделан в виде единой ленты событий по датам (заседания,
   сроки этапов, плановые оплаты, контрольные даты), а не в виде
   классической сетки-месяца — это проще читать на ноутбуке и планшете и
   не требует лишних кликов, чтобы увидеть все типы событий сразу.
8. **Пароль на вход в приложение** при локальном запуске не спрашивается —
   приложение предполагается для использования одним человеком локально на
   своём компьютере, и лишний пароль здесь только мешал бы. Экран входа
   появляется автоматически, только если задать переменную окружения
   `APP_PASSWORD` — это происходит при размещении в интернете (см.
   `DEPLOY.md`), где без пароля данные были бы доступны кому угодно по
   ссылке. При локальном запуске для защиты экрана используйте блокировку
   экрана операционной системы; она не связана с шифрованием файла базы
   данных (см. раздел 5 выше).
9. **Восстановление из резервной копии** требует ручного перезапуска
   приложения после восстановления — это сделано намеренно, чтобы
   исключить работу с "подвисшим" старым соединением к файлу базы данных,
   который был подменён на диске.

## 8. Если что-то пошло не так

- **Чёрное окно закрылось с ошибкой** — прочитайте последнюю строку с
  текстом "ОШИБКА", в ней обычно написано, что не так (например, не
  установлен Node.js).
- **Порт 3000 занят** — если у вас уже запущено другое приложение на этом
  порту, закройте его или обратитесь за помощью, чтобы поменять порт.
- **Показалось, что данные пропали** — не паникуйте: в папке
  `data/backups/` лежат резервные копии за последние запуски, ими можно
  восстановиться через «Настройки → Данные и резервные копии».
- **Нужна помощь** — сохраните файл из `data/backups/` (самый свежий) и
  текст ошибки из чёрного окна перед тем, как обращаться за поддержкой.

## 9. Технические детали (для разработчика)

- Next.js (App Router) + TypeScript (strict) + Tailwind CSS.
- SQLite (`data/legal-practice.db`) + Drizzle ORM, миграции в `drizzle/`.
- Все денежные суммы хранятся в **копейках** (целые числа), время — в
  **минутах**, проценты — в **базисных пунктах** (1% = 100 б.п.).
  Единственный модуль с финансовыми формулами: `src/domain/calculations.ts`.
- Тесты формул: `npm test` (Vitest, включая все обязательные примеры из
  ТЗ). Сценарные тесты: `npm run test:e2e` (Playwright).
- Команды:
  - `npm run dev` — запуск для разработки;
  - `npm run build` / `npm start` — продакшн-сборка и запуск;
  - `npm run db:generate` — сгенерировать новую миграцию после изменения
    `src/db/schema.ts`;
  - `npm run db:migrate` — применить миграции к текущей базе;
  - `npm run db:seed` — заполнить стартовые настройки и каталог услуг
    (не перезаписывает существующие данные);
  - `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:e2e`.
- Переменные окружения (необязательны для локального запуска):
  - `DATA_DIR` — путь к папке с базой данных вместо `./data` (используется
    при облачном развёртывании, том монтируется в `/app/data`);
  - `APP_PASSWORD` — если задана, включает экран входа (`src/proxy.ts`);
  - `APP_SECRET` — секрет для подписи сессионной cookie (обязателен, если
    задан `APP_PASSWORD`).
- `Dockerfile`, `.dockerignore`, `docker-entrypoint.sh`, `fly.toml`,
  `.github/workflows/deploy.yml` — облачное развёртывание, подробности в
  `DEPLOY.md`.

# Калькулятор стоимости юридических услуг

Локальное веб-приложение для практикующего юриста: расчёт цены клиенту,
экономически обоснованной цены, трудозатрат и эффективной часовой ставки.
Работает полностью локально, без облака и внешних API. Единственный
источник истины — файл SQLite `./data/legal-pricing.db`.

Для нетехнической инструкции по запуску смотрите **README_FOR_ILYA.md**.

## Технологии

Next.js (App Router) · TypeScript (strict) · Tailwind CSS · Radix UI
(shadcn-style компоненты) · SQLite + better-sqlite3 · Drizzle ORM · Zod ·
React Hook Form · Recharts · Vitest · Playwright.

## Команды

```bash
npm install        # установка зависимостей
npm run dev         # локальная разработка (http://localhost:3000)
npm run build        # production-сборка
npm start            # запуск production-сборки
npm run typecheck    # проверка типов TypeScript
npm run lint         # ESLint
npm test             # unit-тесты формул (Vitest)
npm run test:e2e      # сквозные тесты (Playwright, поднимает свой dev-сервер)
npm run db:generate   # сгенерировать новую миграцию после правки src/db/schema.ts
npm run db:backup     # создать резервную копию базы вручную из терминала
```

## Ключевые решения, принятые самостоятельно

Так как в ходе разработки нужно было двигаться быстро и не блокироваться на
уточнениях, часть неочевидных решений принята автономно. Они задокументированы
здесь, чтобы их можно было пересмотреть:

- **Расположение проекта.** В корне репозитория уже лежали файлы несвязанного
  сайта (Fiat). Чтобы не удалять чужую работу, проект создан в подпапке
  `legal-pricing-app/`, а не в корне репозитория.
- **Next.js 16 в этом окружении отличается от стандартного** (см.
  `AGENTS.md` в корне проекта) — `params`/`searchParams` асинхронны, Turbopack
  используется по умолчанию, `next lint` заменён на прямой вызов ESLint.
  Учтено во всех страницах и командах.
- **Все страницы, читающие данные из SQLite, помечены `export const dynamic =
  "force-dynamic"`.** Без этого Next.js во время `next build` статически
  пререндерит такие страницы один раз и будет отдавать устаревшие данные в
  production — это критично для инструмента, где данные меняются постоянно.
- **Гонка при инициализации базы.** `next build` параллельно импортирует
  серверные модули в нескольких воркерах, из-за чего миграции и первичный
  засев данных могли запуститься одновременно в двух процессах. Миграции
  оборачены в try/catch, игнорирующий «table already exists»; засев
  справочника использует `onConflictDoNothing()` на вставке настроек как
  примитив атомарной блокировки (кто вставил — тот и сеет остальное).
- **PDF клиенту** реализован через системную печать браузера
  («Печать → Сохранить как PDF»), а не через отдельную библиотеку генерации
  PDF — это не требует дополнительных зависимостей, полностью офлайн и даёт
  предсказуемый результат печати.
- **Тема оформления** переключается вручную (иконка в шапке) и запоминается в
  `localStorage`; по умолчанию берётся системная тема. Само значение темы —
  это единственное, что осознанно хранится не в SQLite (это настройка экрана,
  а не данные практики).
- **Учёт времени в дороге** — доля учитываемого времени в дороге берётся из
  настроек (`travelMinutesCountedRatioBps`, по умолчанию 100%) и применяется
  к введённому в мастере времени в дороге при расчёте плановых часов.
- **Ставка "срочность"** относится только к конкретной строке (услуге/этапу),
  к которой она указана в мастере, а не ко всему делу — как и требует ТЗ.
- **Редактирование сохранённого расчёта** (`/calculations/[id]/edit`)
  переиспользует мастер создания: `originalBasePriceKopecks`/
  `originalPlannedMinutesPerUnit` при повторном редактировании берутся из уже
  сохранённых значений (а не из текущей цены в справочнике услуг) — так
  отслеживание «изменено вручную» остаётся корректным относительно предыдущей
  сохранённой версии, а не переписывает историю.
- **Номер расчёта** — сквозной счётчик (`MAX(number) + 1`); версии одного
  расчёта (кнопка «Новая версия») сохраняют тот же номер и увеличивают
  `version`, дубликаты (кнопка «Дублировать») получают новый номер и не
  связаны с историей версий оригинала.

## Данные и резервное копирование

- База — `./data/legal-pricing.db` (режим WAL).
- При каждом запуске сервера создаётся резервная копия в
  `./data/backups/`, хранятся последние 10 копий.
- Ручной экспорт базы в JSON и восстановление из JSON (с проверкой структуры
  перед применением) — на странице «Настройки».
- Экспорт отдельного расчёта в JSON/CSV — на странице расчёта.
